# 实施记录

## 第一版本地 Web Demo

实现内容：

- FastAPI 提供 HttpOnly Cookie User/Session、SQLite 元数据、Workspace 文件 API、安全 ZIP upload/download、SSE、Sandbox Runtime 和 streaming LLM Relay。
- 一个活跃 Session 复用一个长期 `mycode agent --continue` 进程；Sandbox 以非 root 用户运行，只挂载 Workspace 和 MyCode state。
- Vue/Vite 使用 `/mycode/` base 与 `/mycode/api/*` proxy，提供文件树、预览、上传、下载、终端输出、消息输入和权限按钮。
- 真实 Provider Key 只在 FastAPI Host，Docker command/env 只包含内部 Relay token。
- Browser 多行消息在 CLI stdin 边界折叠为单行；原始消息不被覆盖，Permission `y\n`/`n\n` 保持独立。

历史验证：Server tests 为 `35 passed, 1 skipped`；skip 是 Windows symlink 权限。Vue dependency install、production build 和 dev server `/mycode/` HTTP 200 已通过。Docker trixie build 在外部 Debian APT 502 失败，base 后来固定为 `python:3.11-slim-bookworm`，尚未继续 build。

## 拆分为独立仓库

目标：把原 `mycode-project/server/` 迁移为同级 `mycode-web/`，移除 `server/` 外壳，不复制私有配置、运行数据、环境、前端依赖或构建产物。

路径适配：

- `ServerSettings` 继续由 `app/config.py` 的位置推导 Web repo root，默认数据目录变为 `mycode-web/data/`。
- README、tests、ignore 文件和命令全部以 `mycode-web` 根目录为基准。
- Sandbox Dockerfile 通过 BuildKit named context `mycode` 获取外部 MyCode root lock 与源码。
- PowerShell 和 POSIX shell build scripts 都要求调用方传入 MyCode source directory，不保存开发者绝对路径。

本轮只执行仓库拆分、路径适配、独立 Git 初始化、Server tests 和 Vue build；不执行 Docker build、Sandbox smoke、Provider E2E、commit 或 push。

## Runtime Pool、FIFO Queue 与生命周期

- `ServerSettings` 统一承载最大存活数、Queue 上限、Docker memory/swap/CPU/PID 限制、2 小时 runtime TTL、14 天 Session retention 以及两个后台任务间隔。
- `RuntimeManager` 使用一把进程内 `asyncio.Lock` 原子完成 slot 预留、状态判断、idle victim 选择和 FIFO 出队；Docker 启动、stdin/stdout、进程终止等等待均在锁外。
- 两个 slot 已满时优先回收 `last_activity` 最早的 idle runtime；全部处于 running/waiting_permission 才排队。turn 回到 `you> ` 后，如 Queue 非空，会立即交出该 runtime 的 slot 并启动队首。
- runtime eviction、TTL 和 Queue handoff 只停止 Sandbox process，保留 `workspace/`、`mycode_state/` 和 SQLite Session。等待权限超过 TTL 时清除 pending permission，并通过 SSE 通知前端 runtime 已过期。
- `SessionLifecycleService` 根据 SQLite `last_active_at` 做 14 天清理：先停止残留 runtime，再安全删除 session root 下的单个目录，最后删除 Session metadata。
- FastAPI lifespan 启动 runtime sweeper 和 session cleanup asyncio tasks，启动时先清理一次过期 Session；shutdown 取消后台任务、终止全部 runtime 并关闭 Relay client。
- Vue 继续复用 `runtime_status` SSE，只增加 `queued` 状态、最小排队说明与发送按钮禁用逻辑。

本轮按约束不执行 Docker build、Sandbox E2E 或 Provider E2E。

验证结果：完整 Server tests 为 `48 passed, 2 skipped`；两个 skip 均是当前 Windows 账户不能创建目录 symlink。Vue/Vite production build 通过，`dist/` 正常生成且继续被 Git 忽略。

## 部署前单 Worker 与 orphan Sandbox 清理

- 第一版 Runtime Pool、FIFO Queue 和锁均为进程内状态，部署固定使用单 FastAPI worker，不引入 Redis 或共享 Queue。
- 每个 Sandbox container 带 `mycode-web.managed=true` 和 `mycode-web.session=<session_id>` labels。
- FastAPI startup 仅通过精确 managed label 查询，并以 `docker rm -f` 停止、删除异常退出遗留的 container；不按名称模糊匹配，也不删除 Workspace、MyCode state 或 SQLite Session。
- Docker 查询、停止或删除失败会记录 warning；startup 继续，避免 Docker 暂时不可用导致整个 Web 服务无法启动。

本轮完整 Server tests 为 `51 passed, 2 skipped`；未执行 Docker build 或 E2E。

## 多 Session Web 产品体验与运行逻辑

- HttpOnly Cookie 只标识 Web User；SQLite 使用 Web User `1:N` Session、Session `1:N` Console Event 的最终结构，不保留旧 singleton Session fallback。
- API 全部显式使用 `/mycode/api/sessions/{session_id}/...`，并验证 Session 属于当前 Cookie User。Vue 使用 `/mycode/?session=<id>`，支持创建、列表、切换和删除 Session，同一浏览器不同标签页可独立选择 Session。
- 打开 Session 时 Vue 先渲染页面，再并行读取 metadata、Workspace tree、Console history 并连接 SSE；`activate` 只做快速 admission，Docker/MyCode startup 在 RuntimeManager 的后台 task 中完成。重复 activate 不重复启动，starting 时发送消息等待同一个 Runtime ready。
- Session 删除依次停止自己的 Runtime、停止 watcher、删除该 Session 的 Workspace/MyCode state，最后删除 SQLite metadata；外键级联删除 Console history，不影响其他 Session。
- Workspace 新增文件和目录删除，拒绝 root、path traversal、边界逃逸及 symlink。`watchfiles` 按 Session 观察真实目录，create/modify/delete/rename 变化通过 `workspace_changed` SSE 通知前端 debounce 刷新 tree 和 Preview。
- Console 不再模拟可输入的 PTY Terminal，而按 You、Assistant、Tool、Permission、Error 展示。Web 层过滤确定的 CLI wrapper 噪声，将输出按行/角色聚合后持久化，每个 Session 最多保留 500 条。
- Runtime exit code `0` 视为正常 stopped；非零退出才进入 error。主动 eviction、Session delete 和 shutdown 不制造崩溃错误。Permission request、pending 状态和 `y\n`/`n\n` 写入严格绑定 Session。

本轮不修改 MyCode Core、Dockerfile、部署脚本或服务器配置，也不执行 Docker/Provider E2E。最终完整 Server tests 为 `64 passed, 3 skipped, 1 warning`；3 个 skip 都是当前 Windows 账户不能创建 symlink，warning 是 Starlette TestClient 的上游弃用提示。`npm ci` 无漏洞，Vue/Vite production build 通过，`/mycode/` base 保持不变。
